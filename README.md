# 《NULL：最後一桌》

1–8 人線上合作的第一人稱烹飪＋恐怖遊戲。每位玩家選一張**缺陷卡**：有做不好的事、比別人強的地方，以及隊友能實際幫你的操作。
缺陷卡取代了舊版的盲區員／靜默員／失語員三個固定角色（見 [`docs/FLAW_CARDS.md`](docs/FLAW_CARDS.md)）。

16 張卡全部可以選：

| 階段 | 卡 | 一句話 |
|---|---|---|
| A | **D01 幻聽外場** | 聽得到還沒出現的訂單，也聽得到根本不存在的；隊友到出餐口核對 |
| A | **D02 耳背砧板** | 聽不清楚聲音提示，但連續備料越切越快；隊友拍肩叫他 |
| A | **D03 味覺失調者** | 嚐不出鹹淡，卻會在鍋子出事前收到預警；隊友試吃回報 |
| A | **D04 沉默侍者** | 不用遊戲內語音，靠標記與交接溝通；在餐廳與端盤時跑得快 |
| A | **D15 健忘助手** | 一次只記得兩張單；專注一張單時最快；看單、覆誦 |
| B | **D06 奶油手** | 切菜快三分之一，拿著東西跑會失衡（1.6 秒挽救窗口，隊友可以接住） |
| B | **D09 單手廚師** | 清洗、擦砧板快；打蛋、盛湯需要隊友扶穩或夾具 |
| B | **D10 怕火廚師** | 不碰火源（手套自救）；一次量兩種調味料、冷盤專精 |
| B | **D11 潔癖主廚** | 不碰髒盤與垃圾（托盤、踏板）；洗碗擦砧板快一倍、提早發現汙染 |
| C | **D07 巨人助手** | 過不了低門楣；最上層伸手就拿、搬貨快 |
| C | **D08 小矮人學徒** | 搆不到最上層、看不到湯鍋裡；鑽得過只有他過得去的窄縫 |
| C | **D12 幽閉外場** | 進不了冷藏室；開放空間移動快、交接距離遠 |
| C | **D13 暴衝快遞** | 直線衝到 1.4 倍速，轉彎與急停很難 |
| D | **D05 大嗓門** | 一聲召集全隊收到，但身邊的人會暫時聽不清楚 |
| D | **D14 嗜睡學徒** | 睡意看得到、會睡著 5 秒；清醒時能同時顧兩個爐子 |
| D | **D16 定時噴嚏** | 每 30 秒一個噴嚏（3 秒前兆）；鼻子很靈 |

所有的互助操作——交接、拍肩、便條、標記與回應、覆誦、試吃回報、接住、扶穩、接管爐子、召集、路線箭頭——都由伺服器判定。

深夜的餐廳只剩你們幾個人。單會從出餐口印出來：照標準做的**招牌菜**與每晚兩道**今日特餐**，以及只給條件、做法由你們決定的**主廚委託**。
餐廳最遠的那張桌子坐著一位從來不點餐的客人；後門外，有東西會被廚房的噪音吸引進來。

## 起始頁面與和朋友一起玩

打開遊戲先看到起始頁面：**開始遊戲**、**教學**、**設定**、**說明**（Windows 應用程式另外有**繼續遊戲**、**離開**）。
**教學「第一班」**：一個人、不計時，跟著提示做一道煎蛋吐司（看單 → 查食譜 → 拿吐司 → 烤 → 拿蛋 → 煎 → 裝盤 → 調味 → 出餐），最後認識那位客人和後門的東西；第一次按「開始遊戲」會建議先走一遍，隨時可以跳過。步驟由伺服器依廚房的實際狀態判定（`server/src/kitchen/tutorial.ts`）。
**連續七晚（營業日誌）**：大廳裡房主選「第幾晚」。每晚多一點變化——新的主廚委託、後門的東西多一種行為（更敏感、待更久、更快回來、更快、追更久）、那位不點餐的客人坐得越來越近、動得越來越快；開班前讀一段，營業到一半出單機會印出一張「不是訂單的單」，打烊後再一段。第七晚，那位客人會點餐。讀過的故事收在起始頁面的「營業日誌」；房主模式的存檔記得第幾晚（`shared/src/nights.ts`）。
**無盡模式**：大廳裡房主選「無盡模式」。每天抽幾個隨機的考驗（急性子、客滿、缺貨、碗盤不夠、那位客人坐近了、牠餓了、牠耳朵很靈、牠很善變、牠不想走、牠變快了、後門鎖壞了），天數越多考驗越多，基本難度也一天比一天高（有上限）；一天之內跑單超過上限（3＋人數÷2）就提早打烊、這一輪結束，撐過就接下一天。紀錄存在自己的電腦（`shared/src/endless.ts`）。
**後門的東西**：餓了先在後門外刮門 6 秒（全隊都收到警告）——這段時間到監視器鎖後門就進不來；進門後追最近的人（直接知道你在哪，躲進置物櫃或跑進餐廳才甩得掉），每 20 秒換追另一個最近的人，待滿 40 秒從後門離開（2026-10 試玩後調弱：飢餓值門檻 110、追人 3.1 m/s、撲抓前搖 1 秒）；入侵後可以丟東西砸牠（愣住 3 秒）或用監視器的緊急照明逼退牠；大廳可以勾「沒有怪物」；出現時換成緊張的音樂。
**簡單的物理**（`shared/src/physics.ts`、`server/src/kitchen/physics.ts`，伺服器判定、會存進存檔）：地上的積水（湯開大火滾太久會溢出來、液體或盤子裡的湯打翻、蛋摔破、後門的東西身上滴下來）跑步踩到會滑 1.6 公尺、手上的東西飛出去、跌倒的聲音會引來怪物，按 X 擦乾或放 2 分半會乾；丟東西走固定的拋物線；不能穿過隊友，跑步撞到人會把對方推開、對方手上的東西會晃（停下來就穩住，不然會掉）；撞上那位客人會被彈回來。畫面上：積水會反光、快乾時變淡，滑倒時鏡頭傾斜跌坐，掉在地上的東西會彈兩下。
**音樂**：起始頁面與遊戲中有程式即時合成的 16-bit 背景音樂（偏陰沉、音量偏小），設定裡可以另外調「背景音樂」音量（`client/src/audio/music.ts`）。
和朋友一起玩**只要講 6 碼的房間代碼**——朋友用網頁版或應用程式都能輸入代碼加入，也可以複製邀請連結。

## Windows 應用程式（可以存檔）

除了網頁版，也有 Windows 應用程式（`desktop/`，Electron）。房間開在房主自己的電腦上：**整班存檔／讀檔**、每 30 秒自動存檔、暫停；按「和朋友一起」，程式會開 Cloudflare 的免費通道，並把房間代碼登記到線上伺服器的查詢處，朋友在任何地方輸入代碼就能加入。
設定、按鍵、料理圖鑑與委託紀錄存在電腦的檔案裡，可以匯出、匯入。使用方式、架構與建置見 [`docs/DESKTOP.md`](docs/DESKTOP.md)。

## 設計原則（摘要）

1. **料理系統是確定性的，有真正的技術上限。** 火力有熱慣性與餘溫、切法改變受熱速度、刀工看節奏穩定度、調味有固定量匙、評分五個項目各有原因與操作紀錄。同樣的操作永遠得到同樣的結果。
2. **恐怖系統只能影響「位置、安全、感知、隊伍」，不能碰食譜、火候公式、食材狀態或評分。** 怪物出現時你可能得丟下爐子去躲，但爐子上的蛋會照同一套規則繼續煎——焦掉是你的決定造成的，不是怪物「施法」。
3. **恐怖不是另一個倒數計時器。** 怪物有可以學習的規則（噪音、視線、燈光、蹲下、防火門、置物櫃），沒有隨機秒殺；客人只在沒人看的時候移動。
4. **菜品要有自由度。** 主廚委託只給條件（「酸酸甜甜、我不吃蛋」「只能用三種主要食材」「外酥內軟」），用公開的口味模型與結構化條件判定；不照食譜做的料理也會被認出來、取名字、評分。

完整設計見 [`docs/GAME_DESIGN.md`](docs/GAME_DESIGN.md)；料理模型的所有數字見 [`docs/KITCHEN_MODEL.md`](docs/KITCHEN_MODEL.md)；威脅的狀態機見 [`docs/THREATS.md`](docs/THREATS.md)。

## 功能

- React + TypeScript + Vite 前端，Three.js／React Three Fiber 第一人稱 3D 場景（餐廳、廚房、冷藏室、乾貨室、後走廊；24 個工作站、18 種）
- Node + Express + Socket.IO 權威伺服器：房間（6 碼代碼、1–8 人）、選缺陷卡、位置與速度驗證、固定步長（0.1 秒）的廚房模擬、`kitchen:action`（`requestId` 去重）、斷線重連
- 料理：44 種食材（分類分頁拿取）、27 道食譜（3 道招牌菜＋24 道新食譜）、20 種主廚委託；平底鍋、湯鍋（可以撈起來）、烤麵包機、烤箱、攪拌碗（麵糊、餡料、拌料）、水槽浸泡；自由料理判定（已知／變體／新創／失敗、依內容取名、烹調／風味／搭配／質地四項品質）；本機的料理圖鑑與委託紀錄
- 食材狀態：多維（清洗、去皮、切法、刀工、新鮮度、中心溫度、熟度、兩面上色、汙染、烹調方式、調味）、4 段火力與熱慣性、刀工節奏、量匙調味、試吃、溫度計
- 評分：製程 30／火候 25／刀工 15／調味 20／裝盤 10，每一項附原因；效率另外記錄；食品安全是上限門檻；每份食材的操作紀錄
- 缺陷卡：16 張全部開放（Phase A–D）。FlawSystem 是唯一的判定者（型別化效果設定、可用 `FLAW_CONFIG` 調整、遙測、重連恢復）；每位玩家收到的快照包含只給自己的缺陷狀態
- 共用系統：交接、拍肩、便條、標記、覆誦、試吃回報、接住失衡的東西、扶穩、接管爐子、召集、路線箭頭；碗盤循環（回收窗口、碗盤架）、地上的東西、交接架、低門楣、低矮窄縫、最上層存貨
- 感知：食材的外觀／聲音／觸感描述；廚房的聲音（油爆、湯滾、乾鍋）是空間音效
- 威脅：怪物（刮門預警 6 秒／追最近的人／20 秒換目標／預備撲抓／待 40 秒離開、丟東西砸牠、緊急照明逼退，用細格子 A* 繞過家具追，不打轉、不卡住）、被抓的過場、永遠不點餐的客人（沒人看才會動）、置物櫃、鐵籠救援與自己掙脫（單人 7 秒）、防火門、監視器
- 角色：廚師、怪物、四位一般客人、那位客人都是程式產生的 PS1 風格低多邊形蒙皮模型（Blender bpy），各有自己的動畫；一般客人依照還沒出的單坐在桌邊（見 [`docs/CHARACTERS.md`](docs/CHARACTERS.md)）
- 介面：HUD 預設 85% 大小，可在操作說明裡調整（70–120%）；自訂按鍵（開始頁與遊戲中 H，每個動作兩個鍵）
- 物品欄：左手、右手、菜籃 2 格（B 鍵或滾輪換手，大東西要用雙手，單手廚師只有一隻手）；一次拿 1–4 份；注視冷藏架／乾貨架按數字鍵直接拿（Shift＋數字拿滿）；中島旁有兩個成品架（肉類／蔬菜與其他）
- 開班前讀完操作說明才開始計時（全員準備好，或房主決定不等；`READY_GATE=0` 關掉）
- 語音：內建 WebRTC，所有人互通（沉默侍者不能發話），伺服器驗證 signaling
- 無障礙選項：聲學地標、工作站指引音（音高代表種類）、語音播報（舊版盲區員系統的保留部分，見 [`docs/BLIND_NAVIGATION.md`](docs/BLIND_NAVIGATION.md)）
- 信號器（敲擊／燈號／符號／手勢，含「救我」「危險」「幫我顧爐子」）與所有人都能用的標記工具
- 開發者工具（只在開發環境）：跳過備料、補貨、叫出客人／怪物、被怪物抓（過場）、直接打烊、查看怪物狀態

## 需求

- Node.js 20 以上（建議 22）
- 遊玩：桌機版 Chrome／Edge、耳機、麥克風（選用）

## 安裝與開發

```bash
npm install
npm run dev        # 伺服器 http://localhost:3001 + 前端 http://localhost:5173
```

打開 http://localhost:5173，一人建立房間、其他人輸入代碼加入（最多 8 人；一個人也能開店），每人各選一張缺陷卡後由房主開始。

開發模式下遊戲中按 `` ` `` 打開開發者工具。正式環境（`NODE_ENV=production`）預設關閉，可用 `DEBUG_TOOLS=1` 強制開啟。

## 操作

| 按鍵 | 動作 |
| --- | --- |
| WASD／Shift／C | 移動／跑（很吵）／蹲下（安靜，怪物比較難看到） |
| 滑鼠左鍵 | 看著工作站「拿／放」：手上有東西就放上去，空手就拿起來；裝盤區沒有盤子會自動拿一個再裝盤；出餐口自動選最合適的單出餐 |
| 滑鼠右鍵 | 看著工作站「使用」：備料台一鍵切（常用切法、一致性 80%；想切更整齊就開面板打節奏）、平底鍋翻面／湯鍋攪拌（空鍋時開關火）、開始烤、清洗、攪拌、拿新盤子、監視器鎖後門（牠在裡面時改成緊急照明）；要選擇的事（切法、調味、烤箱溫度、監視器）會打開面板。準星旁會提示左鍵、右鍵會做什麼 |
| 1–9 | 看著工作站直接做（不用開面板）：冷藏架／乾貨架拿第幾種；爐子與烤箱 1 關 2 小 3 中 4 大；烤麵包機 1–5 段；調味區量第幾種（Shift 量 1）；監視器 1 防火門 2 鎖後門 3 緊急照明；面板打開時按面板裡標著數字的按鈕 |
| E | 打開面前的工作站（再按一次或直接走開就關閉）；面前是隊友時打開隊友面板（拍肩、遞東西、覆誦、試吃回報）；面前是客人時請他回座位 |
| F | 接住隊友遞來的東西 |
| T | 把手上的食材丟給準心對著的隊友（7 公尺內；他面向你、手有空就接住，沒接到掉在地上），沒有對著人就丟到前面的地上 |
| X | 撿起地上的東西；附近有積水時擦乾 |
| Tab／R | 訂單板（傳聞、準備提示、標記訂單、專注單）／食譜與口味表 |
| Q／G | 信號器／標記注視中的工作站 |
| 空白鍵 | 切菜時下刀 |

## 環境變數

| 變數 | 預設 | 說明 |
| --- | --- | --- |
| `PREP_SECONDS` | 180 | 開店前的備料時間 |
| `SERVICE_SECONDS` | 900 | 營業時間（超過 7 分鐘時，訂單一輪一輪接下去，越後面越密） |
| `THREATS` | 1 | `0`＝關掉客人與怪物（純料理模式） |
| `DEBUG_TOOLS` | 開發 1／正式 0 | 開發者工具 |
| `FLAW_CONFIG` | — | 缺陷卡的效果數值（JSON，只寫要覆寫的欄位），例如 `{"D02":{"maxStrokeCut":3}}` |
| `TURN_URLS` 等 | — | 語音的 TURN 伺服器（見 `.env.example`） |
| `TRUST_PROXY` | 0 | `1`＝前面有反向代理（Render），用 X-Forwarded-For 判斷來源 IP（房間代碼查詢處的頻率限制） |

## 測試

```bash
npm run typecheck   # shared / server / client / e2e
npm test            # 伺服器：料理模型、評分、驗收、怪物與客人、缺陷卡（每張卡、互助、重連、1–8 人）、Socket 整合
```

瀏覽器端到端測試（五個 Chromium 各選一張 Phase A 的卡，透過 UI 開店、備料、核對傳聞、預警關火、交接、拍肩、看單、出餐、重新整理、打烊結算）：

```bash
npm run build
NODE_ENV=production DEBUG_TOOLS=1 PREP_SECONDS=900 SERVICE_SECONDS=1800 FLAW_CONFIG='{"D01":{"firstFakeMs":3000,"leakLeadMs":150000}}' npm start   # 另開一個終端機
npm run e2e
npm run e2e:blind   # 舊版盲區員的測試關卡（獨立頁面）
npm run e2e:assets  # 角色模型的載入失敗與替換
npm run e2e:bcd     # 缺陷卡 Phase B–D（三桌、11 張卡；伺服器同上，不需要 FLAW_CONFIG）
npm run e2e:playtest # 試玩回饋（單人）：自訂按鍵、數字鍵拿食材、菜籃、成品架、被抓過場、自己掙脫
npx tsx e2e/ui-shot.ts http://localhost:3001 ui-shots                     # 介面與餐廳截圖（1280×720）
npx tsx e2e/preview-shot.ts http://localhost:3001 shots monster:lineup guests:table   # 怪物、客人預覽頁截圖
```

## 已知問題與限制

- **沒有經過真人試玩。** 火候與刀工的手感、怪物出現的頻率（飢餓值 60）、追人的速度（3.8 m/s）、客人的節奏（7 秒）、班次長度與出單密度、缺陷卡的數值，都是依規則挑的初始值，需要實際遊玩調整。數值集中在 `shared/src/kitchen/*`、`server/src/kitchen/threats/*` 的常數與 `DEFAULT_FLAW_CONFIG`（可用 `FLAW_CONFIG` 覆寫）。
- **房間存在記憶體**：線上伺服器重啟會清空所有房間（查詢處的代碼登記也是，房主的應用程式 45 秒內會重新登記）；只適合單一實例。要存檔請用 Windows 應用程式。
- **Windows 應用程式沒有程式碼簽章**：第一次執行會看到 SmartScreen 警告（「其他資訊」→「仍要執行」）。和朋友一起玩用的是 Cloudflare 的免費快速通道，沒有保證可用時間；連不上時可以改用線上伺服器開房（不能存檔）或區網模式。
- **公開狀態包含精確數值**：廚房快照裡有食材的熟度與溫度（畫面不顯示，只用來產生描述與顏色）。打開瀏覽器開發者工具的玩家看得到。這是合作遊戲，暫時接受（味覺失調者的預警由伺服器推算、只送給本人，但鍋溫本身仍在公開快照裡）。
- **聲音全部即時合成**：油爆、湯滾、怪物的呼吸與腳步在一般耳機上的辨識度未經測試。
- 3D 場景只在軟體算繪下截圖確認過，沒有在真實 GPU 上量過幀率。
- 角色、怪物、客人都是程式產生的原型模型（可以用 manifest 的 overrides 換成正式模型，目前只支援廚師）。
- 遊戲無法、也不嘗試阻止外部通話軟體；遊戲機制不依賴語音。
- 8 人語音是 P2P 網狀連線，弱網路下可能吃力（需要 TURN）。
- 缺陷卡的數值都是第一版，還沒有真人試玩（見 docs/FLAW_CARDS.md〈已知限制〉）。
- 只支援桌機（鍵盤＋滑鼠）。
