# 測試計畫

```bash
npm run typecheck   # shared / server / client / e2e
npm test            # server/test
npm run build
NODE_ENV=production DEBUG_TOOLS=1 PREP_SECONDS=900 SERVICE_SECONDS=1800 FLAW_CONFIG='{"D01":{"firstFakeMs":3000,"leakLeadMs":150000}}' npm start   # 另一個終端機
npm run e2e         # 五個 Chromium（五張 Phase A 缺陷卡）的瀏覽器端到端測試
npm run e2e:bcd     # 三桌 11 個 Chromium（Phase B–D 的 11 張卡）：失衡掉落與撿起、雙手工序與扶穩、手套與雙調味、托盤洗碗、召集與回應、睡著與叫醒、噴嚏與接住、最上層、低門楣、冷藏室、湯鍋、窄縫、慣性
# 軟體算繪很慢的機器（例如 2 核心的雲端容器）跑 e2e:bcd 時，可以放寬幾個互助的計時，讓測試不被畫面速度影響（規則不變）：
#   FLAW_CONFIG='{"D09":{"steadyMs":20000},"D05":{"rallyMarkMs":30000},"D16":{"windowMs":4000},"D08":{"peekHoldMs":30000}}'
#   只跑某幾桌：TABLES=BC npm run e2e:bcd
npm run e2e:playtest # 單人：開始頁人數、自訂按鍵（互動改成 T）、注視冷藏架按數字直接拿與 Shift 拿滿、菜籃、成品架肉菜分開、被抓的過場（凍結時間點截圖）、單人自己掙脫鐵籠
npm run e2e:blind   # 舊版盲區員測試關卡（獨立頁面）
npm run e2e:assets  # 角色模型的載入失敗與替換
```

## 1. 驗收條件對照（規格 6.2）

| # | 驗收條件 | 測試 |
| --- | --- | --- |
| 1 | 相同食材、相同設備、相同操作序列 → 相同結果 | `cooking.test.ts`「驗收 1」：跑兩次同樣的班次，出餐結果與所有食材狀態逐一相同 |
| 2 | 有怪物和沒怪物，料理規則完全相同 | `cooking.test.ts`「驗收 2」：怪物與客人在場時同樣的操作得到完全相同的料理結果 |
| 3 | 離開時沒關火，食物照規則繼續煮 | `cooking.test.ts`「驗收 3」：為了躲怪物離開爐台，蛋依正常規則煎到焦 |
| 4 | 威脅不能直接把食物設成燒焦 | `cooking.test.ts`「驗收 4」：靜態掃描 `threats/`，沒有任何改變食材或評分的途徑；`ThreatWorld` 介面不暴露料理資料 |
| 5 | 品質紀錄能追查失誤 | `cooking.test.ts`「驗收 5」：照食譜接近滿分、各種失誤分別扣在對應項目並附原因、品質與速度分開、食品安全上限 |
| 6 | 每個人都能做基本料理工作 | `cooking.test.ts`「驗收 6」：16 張缺陷卡**單人**完成煎蛋吐司 ≥ 90 分（怕火廚師用手套），八人桌的第 8 席也能；`flaws-bcd.test.ts` 另外驗證 B–D 每張卡的限制、補償、互助；瀏覽器 e2e 由五張卡分工完成一道菜 |
| 7 | 怪物的每個狀態都能測試 | `threats.test.ts`：出現、噪音吸引、調查、追逐、視線（距離、牆、黑暗、蹲下）、預備、逃脫、搜索、放棄、置物櫃、鐵籠、防火門 |
| 8 | 重連不會造成重複轉換或重複計分 | `cooking.test.ts`「驗收 8」：同一個 `requestId` 只執行一次；`integration.test.ts`「斷線與重連」：重連後重送的操作不會重複執行 |

## 2. 伺服器測試（`server/test`）

- `cooking.test.ts`：料理模型（熱慣性、熟度、切法、刀工、口味）、食材狀態機、主廚自選、驗收 1–6、8、系統界線
- `threats.test.ts`：怪物與客人的每一條規則（刮門 6 秒預警、刮門時鎖後門就進不來、追最近的人且不追餐廳裡的人、20 秒換目標、撲抓後追下一個、躲進置物櫃、待 60 秒離開、防火門）
- `monster-nav.test.ts`：格子尋路（每個巡邏點到每個工作站都有路且不穿牆、防火門繞路）、鎖定後繞過中島抓到人、從各處追各工作站前的玩家每秒都在前進（不卡住）、20 秒內不換目標
- `playtest-feedback.test.ts`：單人 7 秒／有隊友 18 秒自己掙脫（含噪音、隊友先撬開）、物品欄（左右手＋菜籃的放置順序、用掉後補手與換手、拿著盤子還能拿食材、自動換手、手動換手、雙手搬貨箱、單手廚師只有一隻手）、全部放回、成品架肉菜分開與容量、噴嚏不連打
- `dish-expansion.test.ts`：料理沙盒擴充第一階段——44 種食材的資料完整性（分類、標籤、質地、熟度區間、口味範圍、生肉海鮮的汙染與安全溫度、架上都有存貨）、新切法（切絲、擠汁、壓碎）、海鮮汙染砧板與放肉類架、白米只在水裡會熟、水槽接水與湯量、米粉浸泡（泡軟才能炒、泡太久會爛）、烤箱預熱與兩面上色、攪拌碗（麵糊、餡料的主體、液體不能拌、拌好不能再洗切放回、裝盤展開與受熱繼承）
- `free-cooking.test.ts`：自由料理核心——不選食譜做出薑香豬肉高麗菜炒（先爆香、搭配、下鍋順序與紀錄）、同樣食材不同處理（炒太久軟爛）與不同烹調方式（炒、水煮湯、燉煲）、麵糊煎餅、奶油培根義大利麵（奶醬）、罕見組合烤盤不算失敗、結果完全可重現、已知食譜（番茄炒蛋）、替代食材的變體（黑胡椒豬肉）、失敗料理與原因（燒焦、生米乾炒、過鹹的培根炒飯、過熟鮭魚、生麵糊、糊掉的烏龍麵、沒熟的雞胸、空盤與只有水、檸檬牛奶結塊）、品質等級、出餐結果附上判定與試吃的「看起來像」
- `recipes-v3.test.ts`：24 道新食譜——資料完整（步驟、品質重點、分類；切法與處理做得到；架上有存貨；液體不下平底鍋）、照食譜資料自動做每一道都被認成這道菜而且品質合格、訂單分數 ≥ 80、每個替代食材都判定成變體而且訂單有分數、今日特餐（不同分類、可重現、後半段、24 道都會輪到、廚房狀態的菜單）
- `commissions.test.ts`：20 種主廚委託——每一種都有一道合格的料理（必要條件全過、合格以上、有獎勵）與一道不合格的料理（正確的違規原因、分數 ≤ 35、沒有獎勵）；資料完整（每個條件都有說明）；硬性條件與品質獨立；分數結構（30／25／20／15／10、時間遞減、最多 100）；獎勵（等級倍率、新創或變體 ×1.2）；排程（入門＋進階、限時委託的等待時間）；異常廚房的溫度計失靈；同一張單只結算一次
- `sandbox-sync.test.ts`：料理沙盒第五階段（Socket）——兩人同時搶最後一份食材（只有一人拿到、庫存不為負）、兩人同時放進攪拌碗再攪拌（只有一份拌料、所有客戶端看到同樣的狀態）、同時出同一張單（只出一次、只計一次分）、重連後拌料／泡水／受熱紀錄／菜單都恢復；怪物抓人時鍋裡、攪拌碗、烤箱的料理狀態和沒有恐怖事件時完全一樣
- `balance.test.ts`：料理沙盒第六階段——300 道隨機料理（不出錯、分數範圍、可重現）、亂做很少到 90 分且高分一定熟度對、沒有一種食材「保證」高分、不能生吃的東西生吃永遠不及格、調味不能繞過風味模型（加越多不會越高、全部加一堆反而扣分、沒調味會被說太淡）、不照食譜的料理也能到優秀而且和食譜差不多、委託的條件不互相矛盾、44 種食材都有用處
- `ready-gate.test.ts`：開班前時鐘不走、不能操作；全員準備好才開始；只有房主能決定不等；斷線的人不擋
- `integration.test.ts`：socket 客戶端：房間流程（1–8 人、選卡）、操作協定、真的走路做菜出餐、耳背砧板的事件過濾、怪物抓人與救援、客人擋路、開發者工具、信號器與標記、語音規則、重連
- `flaws.test.ts`：卡片資料、效果設定、人數適配與出生點、D01／D02／D03／D04／D15 的每一條規則、交接判定、便條、遙測
- `flaws-net.test.ts`：1／2／4／6／8 人經由 Socket 開店並操作、私人資訊不外洩、健忘助手的個人快照、重連後缺陷狀態／計時器／手上的東西／互助標記完全恢復、沉默侍者的移動倍率由伺服器驗證

## 3. 瀏覽器端到端（`e2e/browser-shift.ts`）

五個獨立的 Chromium（軟體算繪），各選一張 Phase A 的卡，透過實際的 UI：

1. 建立房間、四人加入、選卡（16 張中 11 張顯示「即將推出」）、開始營業、進廚房；沉默侍者沒有麥克風、沒有發話連線
2. 耳背砧板削皮後接著切片只要 4 刀（一般 5 刀），畫面上看得到連續備料狀態
3. 開店：幻聽外場聽到傳聞（其他四人的快照裡都沒有）→ 貼上訂單板 → 耳背砧板到出餐口核對 2 秒 → 全隊出單軌出現準備提示
4. 味覺失調者把蛋放上大火 → 燒焦前收到預警 → 關火 → 蛋沒有燒焦
5. 沉默侍者烤吐司、裝盤、調味；味覺失調者試吃「嚐不出」；沉默侍者試吃後用隊友面板回報；出餐、評分收據
6. 健忘助手的出單軌出現想不起來的單（其他人看到完整的單）→ 到出餐口看單 → 貼便條
7. 沉默侍者走到健忘助手旁邊、隊友面板「遞給他」→ 健忘助手畫面出現接住提示 → 按 F → 東西真的換手
8. 幻聽外場走到耳背砧板旁邊拍肩（危險）→ 耳背砧板畫面出現方向箭頭與文字
9. 健忘助手重新整理頁面 → 記憶與手上的東西由伺服器恢復
10. 打烊結算列出每個人的卡、房主帶全隊回到大廳、主控台沒有錯誤

截圖存在第二個參數指定的資料夾。

## 3b. Windows 應用程式（`desktop/test`）

- `smoke.mjs`（Linux 版 Electron＋xvfb；本機另開一個伺服器當「線上伺服器」，假的 cloudflared，通道網址用 Playwright 轉到房主的本機伺服器）：

  **網頁版的朋友**在線上伺服器輸入代碼 → 被帶到房主的網址、自動加入同一個房間（暱稱不留在網址列）→ 兩人開班 →
  關掉程式（自動存檔、代碼從查詢處刪掉）→ 重開，起始頁面的「繼續遊戲」顯示最近的存檔 → 讀檔回到原本的位置、自動重新邀請
